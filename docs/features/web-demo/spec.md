# 웹 체험판 (web-demo) 명세와 설계

- 작성일: 2026-11-20
- 상태: 공개 (https://gilbeot.hyunolike.dev, 2026-11-20)

## 1. 문제

심사자는 Pleos 에뮬레이터를 띄울 수 없다. 사용자는 심사자가 직접 길벗을 체험하기를 원한다(2026-11-20). 브라우저에서 주소 하나로 들어와 출발하고, 이야기를 듣고, 들를지 고르고, 도장을 찍고, 충전 대기 화면까지 볼 수 있어야 한다.

## 2. 핵심 결정: 판단은 실제 앱 코드가 한다

웹에서 판단 로직을 다시 짜면 앱과 어긋난다. 그래서 앱의 Kotlin 코드(`DocentSession`, `AheadTracker`, `TrackPlayer`, `ReplayBackedNavi`)를 JVM에서 그대로 돌려 송파 경로의 주행 기록을 JSON으로 뽑는다. 웹은 이 기록을 재생하고, 갈림길(들를지 묻는 순간)에서 사용자가 고른 기록으로 넘어간다.

- 새 모듈 `web-export`(kotlin-jvm, 실행 가능): `./gradlew :web-export:run`이 `web/data/*.json`을 만든다.
- 기록은 재생 모드(앱의 `pleos` 빌드와 같은 부품 조합, 회전 600m, 좌석 안내, 경로 기준 지나침)로 만든다.

## 3. 기록

- 경로(갈림길 선택의 조합)마다 프레임 목록을 뽑는다. 프레임은 재생 시각 2초마다 하나다(앱 재생 한 걸음과 같음).
- 프레임: 시각, 위치(위도, 경도, 진행 방향), 주행 여부, 남은 시간, 쉼(회전 거리, 안내), 이야기(장소, 단계, 해설, 앞머리, 쪽), 앞의 장소(이름, 거리, 쪽, 소개 가능), 들은 곳, 경유지, 도장, 정차 사유(경유지 도착, 목적지 도착).
- 갈림길: 석촌동 고분군 질문(예/아니요), 방이동 고분군 질문(예/아니요). 출발 전 "여기로 안내"(석촌동, 방이동)도 경로로 둔다.
- 답은 묻고 2초 뒤에 한 것으로 기록한다. 웹은 질문 프레임에서 멈춰 사용자의 답을 기다리고, 10초 동안 답이 없으면 "아니요" 기록으로 이어 간다(앱과 같은 10초).
- 경유지에 서면 기록은 "다시 출발"을 기다리는 지점을 표시한다. 웹은 "계속 안내" 버튼을 눌러야 이어 간다.
- 충전 대기: 목적지와 각 경유지에서 걸어서 갈 곳을 앱의 `nearbyOnFoot`으로 계산해 넣는다.

## 4. 웹 화면

- 정적 사이트 `web/`(HTML, CSS, JS, 빌드 도구 없음). 지도는 Leaflet과 OpenStreetMap 타일. 사진은 앱과 같은 CC0 사진.
- 왼쪽: 차량 화면. 앱의 주행 화면과 정차 화면을 HTML로 옮긴다(같은 문구, 같은 색).
- 오른쪽: 지도. 경로, 장소, 차, 경유지를 그리고, 이야기할 때 그 장소와 쪽을 강조한다.
- 아래: 재생 속도(10배속 기본), 처음부터 다시, 충전 시작(정차 중일 때), 해설 듣기(브라우저 음성 합성, 기본 꺼짐).
- 첫 화면에 체험판이라는 것과, 판단은 실제 앱 코드로 만든 기록이라는 것을 밝힌다.
- 모바일에서도 세로로 쌓여 보인다.

## 5. 공개

Vercel 프로젝트 `gilbeot`(hyunho-jangs-projects)로 공개한다. 주소는 https://gilbeot-three.vercel.app 이다(`gilbeot.vercel.app`은 이미 쓰이고 있어 Vercel이 정한 이름). 처음에 GitHub Pages로 공개했다가 사용자 요청으로 Vercel로 옮기고 Pages는 껐다(2026-11-20).

주소는 https://gilbeot.hyunolike.dev 다(`hyunolike.dev`의 네임서버가 Vercel이라 하위 도메인을 바로 붙였다). Vercel이 정한 https://gilbeot-three.vercel.app 도 같은 곳을 가리킨다.

Vercel 프로젝트를 이 저장소와 연결하고 루트 폴더를 `web`으로 두었다. `main`에 push하면 프로덕션, 다른 브랜치는 미리보기로 자동 배포된다. 정적 파일이라 빌드 설정이 없다. 앱 판단이 바뀌었으면 기록을 다시 뽑아 함께 올린다.

```bash
cd vehicle-app && ./gradlew :web-export:run
```

## 6. 검증

- 내보낸 기록 테스트: 경로마다 마지막 프레임이 목적지 도착이고, 앱 통합 테스트와 같은 쪽(서울공항 오른쪽, 고분군 왼쪽)으로 소개된다.
- 브라우저에서 갈림길 네 가지, 출발 전 안내, 처음부터 다시, 충전을 눌러 본다.

## 7. 확인 (2026-11-20)

- 기록 7개(갈래: 없음, 석촌동, 방이동, 둘 다, 출발 전 안내 석촌동, 방이동, 석촌동 뒤 방이동). `ExportTest`가 갈래 정렬(답하는 프레임까지 같음), 쪽(서울공항 오른쪽, 고분군과 몽촌토성 왼쪽), 목적지 도착, 도장을 확인한다.
- 브라우저(Playwright)로 확인: 출발, 회전 앞 쉼, 석촌동 질문에 "들르기"로 갈래 바꾸기, 경유지 도착과 도장, 충전 카드, 석촌동 "지나가기"와 방이동 "들르기", 계속 안내, 목적지 충전 카드(몽촌토성 14분, 방이동 16분, 에뮬레이터 앱과 같음), 390px 폭에서 가로 스크롤 없음.
- 체험판에서 찾은 앱 버그: 걸어서 갈 곳에 지금 서 있는 곳이 "걸어서 1분"으로 들어감. `nearbyOnFoot`이 150m 안을 빼도록 고쳤다.
- 공개: Vercel 주소에서 페이지, 기록, 사진이 로그인 없이 열리고(HTTP 200), 출발과 "들르기", 경유지 도착과 도장, 지도 타일을 브라우저로 확인했다.
