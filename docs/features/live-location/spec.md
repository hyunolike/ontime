# 실제 위치 SDK로 도슨트 움직이기 (live-location) 명세와 설계

- 작성일: 2026-11-20
- 상태: 구현 완료, 에뮬레이터 확인 (2026-11-20)
- 선행: [live-docent](../live-docent/spec.md), [docent-plus](../docent-plus/spec.md)

## 1. 문제

`pleos` 빌드의 도슨트는 차의 위치를 앱 안에서 재생한다. 심사 항목 "기술 활용성"에서 가장 약한 부분이다. 2026-11-20에 FusedLocation이 `adb emu geo fix`로 넣은 좌표를 받는다는 것을 확인했다(내비는 NMEA 체크섬 문제로 버림). 에뮬레이터에 경로 좌표를 흘려 넣으면 앱은 실제 위치 SDK에서 위치를 받아 실차와 같은 코드 경로로 움직일 수 있다.

## 2. 범위

- 에뮬레이터에 송파 경로 좌표를 흘려 넣는 스크립트 `tools/geo-drive.py`
- FusedLocation 위치에서 진행 방향과 속도를 계산해 `LocationGateway`로 내보내기
- 재생기(`TrackPlayer`)가 시계 대신 실제 위치를 따라가는 모드
- `pleos` 빌드에서 재생 모드와 실제 위치 모드를 바꾸는 시험 명령, 화면 표시

제외: 내비 화면의 차 위치(내비는 여전히 판교에 서 있다), 실차 시험.

## 3. 요구사항

### L1. 위치 스크립트
- L1-1. `ScenarioSongpa.kt`의 경로 문자열과 장소 좌표를 읽어(같은 데이터를 두 번 두지 않는다), 경로를 따라 0.5초마다 `adb emu geo fix <경도> <위도>`를 보낸다. 기본 속도는 앱 재생과 같은 초속 10m의 10배속이다.
- L1-2. `adb logcat -s OnTimePleos`를 함께 읽는다. `-> addWaypoint <이름>`이 나오면 경로에서 그 장소와 가장 가까운 지점까지 달린 뒤 장소 좌표로 들어가 선다. `-> removeWaypoint`가 나오면 그 지점으로 돌아와 이어 달린다. 실제 운전자가 내비를 따라 들르고 다시 나오는 모습이다.
- L1-3. 경로 끝에 닿으면 마지막 좌표를 계속 보내며 선다.

### L2. 위치에서 진행 방향과 속도
- L2-1. `MotionEstimator`(platform-api, 순수 함수)가 연속한 두 위치와 받은 시각으로 속도(m/s)와 진행 방향을 계산한다. 2m 미만으로 움직였으면 방향은 직전 값을 유지하고 속도는 0으로 본다.
- L2-2. `PleosLocation`이 `LocationGateway`를 구현해 `onChanged`를 `Fix`로 내보낸다. FusedLocation의 `heading`은 에뮬레이터에서 0이므로 계산값을 쓴다.

### L3. 재생기가 실제 위치를 따라가기
- L3-1. `TrackPlayer.follow(fixes)`: 받은 위치를 경로에 투영해 달린 거리를 갱신한다. 뒤로 가지 않고, 지금 위치에서 앞쪽 1km 안에서만 찾는다(굽은 길에서 먼 구간으로 튀지 않게).
- L3-2. 따라가는 동안 `fixes`는 받은 실제 위치를 그대로 내보낸다. 이야기와 쪽 계산이 실제 위치로 돈다.
- L3-3. 주행 여부는 속도로 판단한다. 초속 1m 이상이면 주행, 3초 넘게 1m 미만이면 정차.
- L3-4. 경유지가 정해져 있고 그 장소 150m 안에서 섰으면 들른 것으로 본다. 다시 출발 명령이 오면 정차 지점을 풀고, 다음에 정차 지점이나 경로 끝에 닿을 때까지 기다린다(`run()`의 계약은 그대로).
- L3-5. 남은 시간, 다음 회전, 다음 좌우회전은 지금처럼 달린 거리로 계산한다. 시각은 기기 시계다.

### L4. 모드 바꾸기와 표시
- L4-1. `adb shell am broadcast -a io.github.hyunolike.ontime.POC --es poc location-live`로 실제 위치 모드, `location-replay`로 재생 모드. 명령에 공백을 넣지 않는다(`adb shell`이 공백에서 값을 가른다). 정차 중에만 바꾼다(주행 중이면 무시하고 로그에 남긴다).
- L4-2. 실제 위치 모드에서는 칩을 "에뮬레이터 GPS"로, 설명 문구를 "위치는 FusedLocation SDK에서 받습니다. 에뮬레이터에 경로 좌표를 넣어 움직입니다."로 바꾼다. 칩과 설명은 번들의 `StateFlow`가 된다.

## 4. 설계 메모

- `TrackPlayer`에 `following: Boolean` 상태를 둔다. 재생 모드의 동작과 테스트는 바꾸지 않는다.
- 투영은 기존 `canStopAt`과 같은 평면 미터 계산을 쓰되, 검색 범위를 `traveled ~ traveled + 1_000`으로 묶는다.
- `run()`: 따라가는 중이면 출발 처리(들른 경유지 풀기)만 하고 `state.first { 정차 지점이나 끝에 닿음 }`까지 기다린다.
- 경유지 도착 판정에서 정차 지점(`stop.atMeters`)까지 달린 거리를 강제로 맞추지 않는다. 실제 위치가 장소에 들어가 있으므로 `fixes`가 장소 좌표가 되고, 도장은 기존 규칙(80m 안 정차)으로 찍힌다.

## 5. 검증

- 단위 테스트: `MotionEstimator`(속도, 방향, 2m 미만), `TrackPlayer.follow`(투영, 뒤로 가지 않음, 굽은 길, 주행 판정, 경유지 도착과 재출발, run 대기).
- 통합 테스트: 송파 경로 좌표를 위치 흐름으로 흘려 넣어 세 곳 이상이 지날 때의 쪽으로 소개되는지.
- 에뮬레이터: 스크립트를 돌리며 `fused.onChanged` 로그, 이야기 화면, 경유지 들르기와 도장, 다시 출발을 확인한다.

## 6. 구현하며 바꾼 것 (2026-11-20)

실제 위치로 송파 경로를 처음부터 끝까지 돌려 보며 다음을 찾아 고쳤다. 모두 실차 GPS에서도 생길 수 있는 문제다.

| 문제 | 원인 | 조치 |
|---|---|---|
| 방이동 고분군을 "오른쪽"으로 소개(실제로는 왼쪽) | 위치 두 점으로 구한 방향은 꺾은 직후에도 한동안 꺾기 전 방향이다 | 방향이 직전보다 15도 넘게 바뀌는 중에는 새로 소개하지 않는다(`AheadTracker.turning`). 회전 지점을 지나고 60m까지는 그 회전을 아직 앞에 있는 것으로 둔다(`TrackPlayer.TURN_SETTLE`) |
| 서 있는데 3초 동안 "주행 중" | 정차 판정이 "움직이던 차가 3초 넘게 섬"이라 처음부터 서 있는 경우를 다루지 못함 | 처음부터 서 있으면 곧바로 정차 |
| 출발하자 앞의 장소가 사라짐(1) | 따라가기를 막 시작해 실제 위치가 없을 때 재생 속도(초속 10m)를 내보내 엉뚱한 방향을 믿음 | 따라가는 중에는 재생 위치를 정차로 내보냄 |
| 출발하자 앞의 장소가 사라짐(2) | 서 있는 위치가 순간 이동해도 "뒤에서 멀어짐"으로 지나침을 판정함. 명세(움직일 때만)와 코드가 달랐다 | 움직일 때만 지나침을 판정 |
| 남아 있던 위치에서 출발점으로 돌아갈 때 앞의 장소가 사라짐 | FusedLocation이 두 위치 사이를 이어 주어 차가 경로를 따라 뒤로 빠르게 달린 것처럼 보임 | 경로를 따라 30m 넘게 뒤로 가는 위치는 정차로 내보내고, 창 밖이지만 경로 위인 위치(멀리 앞, 300m 넘게 뒤)는 그 자리로 다시 맞춤. 1km 넘게 튀면 속도와 방향을 새로 시작(`MotionEstimator.jumpMeters`) |
| 경유지로 들어가자 방이동 고분군이 사라짐 | 위치만 보는 지나침 판정은 우회에 약함 | 경로를 알면 "경로를 따라 그 장소의 지점을 200m 넘게 지났는가"로 판정(`AheadTracker.passedOnRoute`, `TrackPlayer.hasPassed`). 재생 모드도 같은 규칙 |
| `poc "location live"`가 전달되지 않음 | `adb shell`이 공백에서 값을 가름 | 명령을 `location-live`, `location-replay`로 바꿈 |
| 스크립트를 띄우기 전에 넣은 경유지를 모름, 지난 스크립트가 남아 다른 좌표를 보냄 | 스크립트가 실행 뒤의 로그만 읽음 | 시작할 때 지난 로그를 훑어 남은 경유지를 이어받고, 이미 도는 스크립트를 멈춤. 출발 전 3초 동안 출발점 좌표를 보냄 |

## 7. 에뮬레이터 확인 (2026-11-20)

`location-live`로 바꾸고 `tools/geo-drive.py`를 띄운 뒤, 출발 전에 석촌동 고분군을 "여기로 안내"하고 출발했다.

- `addWaypoint` 뒤 `onWaypointChanged(ADD)`, 칩 "에뮬레이터 GPS", 설명 문구 바뀜
- 서울공항 소개, 회전 앞 쉼, 석촌동 고분군 "5분 뒤 왼쪽 창밖"
- 스크립트가 경로 11,542m 지점에서 석촌동으로 들어가 서고, 앱에 "도착했습니다"와 도장 1/2. 방이동 고분군은 목록에 남음
- "계속 안내"를 누르면 `removeWaypoint`, `onWaypointChanged(REMOVE)`, 스크립트가 경로로 돌아옴
- 방이동 고분군 "3분 뒤 왼쪽 창밖"과 들를지 묻기, 몽촌토성 "4분 뒤 왼쪽 창밖", 위례성대로 앞 쉼, 목적지 도착

테스트: 129개 통과(이전 112개). `TrackFollowTest`, `MotionEstimatorTest`, `LiveFollowTest`(실제 경로 좌표 흘려 넣기, 다시 시작 후 순간 이동, 경유지 우회)가 새로 들어갔다.
