# 1차 EGM 검토 (2026-11-20)

검토 대상: spec.md, design.md, tasks.md 초안. 검토자 두 명이 새 문맥에서 문서와 관련 코드만 받아 검토했다.

- 설계 검토(egm-design): 수정 후 진행 권고. Blocker 3, Major 7, Minor 8
- 구현 준비도 검토(egm-implementation-readiness): 바로 구현 어려움. Blocker 2, Major 8, Minor 11

두 검토의 지적이 많이 겹쳐 하나로 묶었다.

| 지적 | 조치 |
|---|---|
| 에뮬레이터 내비의 `remainTime`이 줄지 않아 도착 표시(`remaining == 0`)가 나오지 않음. 30초 기준 대체도 실제로는 쓰이지 않음 | 화면의 남은 시간과 목적지는 재생 값으로 정함. 내비 값은 로그로만 남김(spec R3-3, 범위 제외) |
| `pleos` 빌드가 `platform-fake`에 의존하지 않아 컴파일 불가 | `pleosImplementation(":platform-fake")` 추가. 재생 부품은 `platform-pleos` 타입을 참조하지 않음(design §1) |
| `pleos` 도슨트의 음성이 정해지지 않음. `PleosSpeech`면 STT 오류로 질문이 곧바로 닫힘 | `ScriptedSpeech(answer=false, 10초, 3.5초)`, `voice=false`(spec R3-9) |
| 정차 지점 직전에 장소가 `passed`로 빠지면 도장이 찍히지 않고 "계속 안내" 버튼이 사라져 진행이 막힘 | 150m 안이면 `passed`여도 넣음. 정차 지점 계산은 평면 미터 기준. 통합 테스트로 두 곳 도장 확인(spec R1-1, R1-5, design §4) |
| 진행 방향이 한 틱만 튀어도 아직 소개하지 않은 장소가 영구히 빠짐 | 진행 방향을 40m 앞 지점 방위로 부드럽게 함. 지나침 기준을 ±100도로 넓힘. 통합 테스트로 세 곳 모두 소개 확인(spec R2-1, R1-5) |
| 출발 전 정차 화면이 비고 "여기로 안내"를 할 수 없음 | 믿을 수 있는 방향이 생기기 전에는 모든 장소를 넣음. 출발 전에는 쪽 없이 직선 거리만 적음(spec R1-7, R5-3) |
| 출발 전 경유지 요청과 첫 `requestRoute` 순서 충돌 | 경로를 먼저 요청하고 내비가 목적지를 알려 온 뒤 경유지를 넣음. 20초 제한(spec R3-5) |
| 내비는 경유지를 받았는데 재생기가 설 수 없으면 둘이 어긋남 | 재생기 가능 여부를 먼저 보고, 마지막 확정 실패 때 `removeWaypoint`로 되돌림(design §2 ReplayBackedNavi) |
| 경유지에 선 채 다른 곳을 고르면 새 경유지가 지워짐 | 들른 경유지를 `visited`로 추적하고 새 경유지를 넣기 전에 지움(spec R3-6) |
| 내비 목적지 id가 맞지 않음, 이전 경로가 남아 있으면 엉뚱한 목적지 표시 | 화면은 재생 목적지만 씀. `known`에 시연 목적지를 넣음 |
| `route`가 내비 값 없이도 곧바로 첫 값을 내야 함 | 재생 값만으로 만들고 첫 값을 곧바로 냄 |
| 칩, 설명, 출발 버튼, CC0 문구가 하드코딩 | `DocentBundle` 문구 필드로 뺌(design §2 app) |
| 사진 저작자가 화면에 없음 | 사진 오른쪽 아래에 저작자와 조건 표시, `fake` 포함(spec R5-2) |
| 장소의 `Source` 값 미정으로 칩이 깜빡일 수 있음 | `pleos` 칩은 항상 "위치 재생". 장소는 `REPLAY` |
| spec §4와 R1-6 불일치 | §4를 R1-6에 맞춤 |
| `PleosLocation.fixes`의 속도 원천 없음 | 실차 위치 연결을 이번 범위에서 뺌 |
| `runCatching`이 스레드 문제를 푼다는 잘못된 문장 | 호출 scope를 적는 문장으로 바꿈 |
| `LatLon`, 경로 데이터, 해설, 회전 목록, 저작자 표시 위치 미정 | design §2, §3에 모두 적음 |
| 통합 테스트 위치와 기대값 미정 | core-session에 두고 기대값 세 가지를 적음(design §4) |
| 로그 순서 수용 기준이 모호 | "requestRoute 다음 시연 목적지의 onDestinationInfo"로 다시 씀(spec R3) |
| `PoiAhead` 등 KDoc이 직선 거리와 맞지 않음 | KDoc 갱신을 T1에 넣음 |
| `LiveStories`가 상태 있는 tracker를 공유 | 단일 수집 전제를 KDoc에 적음 |
| `onError`로 비동기 거절되면 앱은 들어간 것으로 표시 | 로그로 확인. 되돌리기는 미정 사항으로 남김 |

재검토는 하지 않고, 바뀐 기대값은 통합 테스트로 확인한다.
