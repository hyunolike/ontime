# 도슨트 고도화 (docent-plus) 명세

- 작성일: 2026-11-20
- 상태: 구현 완료 (1차 EGM 검토 반영)
- 선행 작업: [live-docent](../live-docent/spec.md) (병합됨, `fda9480`)
- 관련 문서: [설계](design.md), [작업](tasks.md)

## 1. 해결할 문제

live-docent로 `pleos` 빌드가 실제 내비와 함께 움직인다. 2차 PT(12/3~4) 전에 심사 항목(차량특화성, 창의성, 기술 활용성, 사업성)에서 점수를 더 얻을 기능을 넣는다. 사용자가 고도화 목록 전체 진행을 요청했다(2026-11-20).

## 2. 범위

| ID | 고도화 | 이번 범위 |
|---|---|---|
| E1 | 남은 시간에 맞춰 이야기 길이 조절 | 포함 |
| E2 | 좌석 안내(오른쪽은 조수석 쪽) | 포함 |
| E3 | 충전 대기 도슨트 | 포함 |
| E4 | TourAPI로 경로 주변 장소 자동 수집, 오프라인 캐시 | 포함. 키가 없으면 내장 목록 |
| E5 | 음성 안내와 음성 답(서버 모드) | 포함. 키가 없으면 자막 |
| E6 | 앱이 다시 시작돼도 들은 곳과 도장 이어 가기 | 포함 |
| E7 | 경로 재탐색, 경유지 개수 한도 | 확인과 기록 |
| E8 | 사업성 정리(PT 자료용) | 문서 초안 |

제외하고 이유를 남기는 것

- **들르는 데 드는 시간의 실시간 계산.** SDK의 `requestTrip`은 지금 위치에서 한 곳까지의 시간만 준다. 우회 시간을 구하려면 "그곳에서 목적지까지"가 필요한데 이 값을 얻을 방법이 없다. 경유지를 시험 삼아 넣었다 빼면 구할 수 있지만 운전자의 내비 화면을 건드린다. 예시 값을 유지한다.
- **다국어 해설.** 화면 문구가 모두 한국어로 코드에 들어 있어 해설만 바꾸면 반쪽짜리가 된다. PT 이후 과제로 남긴다.

## 3. 요구사항과 수용 기준

### E1. 남은 시간에 맞춰 이야기 길이 조절

- E1-1. 장소마다 기본 해설과 짧은 해설(한 문장)을 둘 수 있다. 짧은 해설이 없으면 기본 해설의 첫 문장을 쓴다.
- E1-2. 이야기를 시작할 때 다음 중 하나라도 맞으면 짧은 해설을 쓴다.
  - 그곳까지 1분이 남지 않았다(거리 / 속도).
  - 다음 회전까지 남은 시간이 기본 해설을 읽는 시간보다 짧다.
  - 소개를 기다리는 다른 장소가 기본 해설을 읽는 동안 소개 범위(3km) 안으로 들어온다.
- E1-3. 읽는 시간은 해설 본문의 글자 수 기준으로 초당 6자로 잡는다(`fake` 자막 시간과 별개).
- 수용 기준(단위 테스트): 위 세 조건 각각에서 짧은 해설이 나오고, 여유가 있으면 기본 해설이 나온다.

### E2. 좌석 안내

- E2-1. 한국 차량은 운전석이 왼쪽이다. 오른쪽 장소는 "5분 뒤 오른쪽, 조수석 쪽에 ○○"로, 왼쪽 장소는 "5분 뒤 왼쪽에 ○○"로 말한다. 운전자에게 고개를 돌리라고 하지 않기 위해 왼쪽에는 좌석을 덧붙이지 않는다.
- E2-2. 화면의 큰 글자("5분 뒤 오른쪽 창밖")는 그대로 두고, 해설 음성과 자막 문장에만 덧붙인다.
- 수용 기준(단위 테스트): 오른쪽 장소의 해설 문장에 "조수석"이 들어가고 왼쪽에는 들어가지 않는다.

### E3. 충전 대기 도슨트

- E3-1. 차가 서 있고(P) 충전 중이면 정차 화면에 "충전하는 동안 걸어서 둘러볼 곳"을 보여 준다. 지금 위치에서 걸어서 20분 안(직선 1.2km, 보행 속도 1.2m/s에 도로 굴곡 1.3배)인 장소를 가까운 순서로 최대 세 곳, 걸어서 몇 분인지와 함께 적는다.
- E3-2. 충전 중인지는 차량 SDK로 판단한다. 충전구가 열려 있으면 충전 중으로 본다(`EvBattery.isEvChargePortOpen`, `registerEvChargePortOpen`). 지원하지 않으면 이 기능을 끈다.
- E3-3. 충전 중에 배터리 잔량을 함께 보여 준다(`getEvBatteryStateOfCharge`). 읽지 못하면 잔량 줄을 빼고 나머지는 보여 준다.
- E3-4. 에뮬레이터에서 시연할 수 있게, 충전구 상태를 바꾸는 방법이 없으면 `poc charge` 시험 동작으로 충전 상태를 켜고 끈다. 이 경우 화면의 출처 표시에 시험 값임을 밝힌다.
- E3-5. 송파 경로에 몽촌토성(목적지에서 777m)을 장소로 더한다. 들르지 않는 곳으로 두되 길가 소개 대상이다.
- 수용 기준(단위 테스트): 충전 중이고 서 있으면 목록이 나오고, 달리거나 충전하지 않으면 나오지 않는다. 1.2km 밖은 빠진다.

### E4. TourAPI 경로 주변 장소

- E4-1. `local.properties`에 `tourapi.key`가 있으면 출발 전에 경로를 따라 2km 간격 지점마다 한국관광공사 TourAPI 위치 기반 관광정보(관광지, 반경 1km)를 조회해 장소 목록에 더한다. 해설은 공통정보의 개요에서 앞의 두 문장을 쓴다.
- E4-2. 이미 들어 있는 장소와 이름이 같거나 150m 안이면 더하지 않는다.
- E4-3. 조회 결과는 앱 저장소에 캐시해, 같은 경로는 통신이 끊겨도 다시 쓴다.
- E4-4. 키가 없거나 조회가 실패하면 내장 목록만 쓴다. 출처 칩에 "관광공사 데이터"가 섞였는지 밝힌다.
- E4-5. 사진은 이번 범위에서 내장 사진만 쓴다. TourAPI 사진은 원격 이미지 로딩이 필요해 다음으로 미룬다.
- 수용 기준(단위 테스트): 실제 응답 형식의 JSON으로 파싱, 중복 제거, 캐시 재사용, 실패 시 내장 목록을 확인한다. 키가 있으면 실제 조회를 한 번 확인한다.

### E5. 음성 안내와 음성 답

- E5-1. `local.properties`에 Pleos Playground 등록 정보(`pleos.tts.clientId`, `pleos.tts.clientSecret`)가 있으면 TTS와 STT를 서버 모드로 등록하고 해설과 질문을 소리로 들려준다. 답은 말("들를래", "아니")과 버튼 중 먼저 온 쪽이다.
- E5-2. 등록이 실패하거나 정보가 없으면 지금처럼 자막과 버튼으로 동작한다. 실패 이유는 로그에 남긴다.
- 수용 기준: 정보가 없을 때 지금 동작과 같다(기존 테스트). 정보가 있으면 에뮬레이터에서 소리가 나는지 확인한다.

### E6. 들은 곳과 도장 이어 가기

- E6-1. 들은 곳, 들르기로 한 곳, 방문 도장을 경로(목적지 id) 단위로 저장한다.
- E6-2. 앱이 다시 시작되면 같은 목적지일 때 저장한 상태로 이어 간다. 목적지가 다르면 새로 시작한다.
- 수용 기준(단위 테스트): 저장한 뒤 새 세션을 만들면 같은 장소를 다시 소개하지 않고 도장이 남아 있다.

### E7. 경로 재탐색과 경유지 한도

- E7-1. 내비가 경로를 다시 잡으면(`onReRouteEnded`) 로그에 남긴다. 앞의 장소는 위치로 계산하므로 다시 계산할 것이 없다는 점을 문서에 적는다.
- E7-2. 경유지는 한 번에 하나만 둔다(이미 그렇게 동작). Pleos 내비의 경유지 최대 두 개 한도 안이다.

### E8. 사업성 정리

- E8-1. `docs/business.md`에 PT용 초안을 쓴다. 대상 고객, 수익 구조(제휴, 스탬프 투어), 확장(다국어, 충전 대기)을 근거와 함께 적는다. 확인하지 않은 수치는 쓰지 않는다.

## 4. 오류 상황

| 상황 | 동작 |
|---|---|
| 충전구 상태를 지원하지 않음 | 충전 대기 화면을 쓰지 않는다 |
| TourAPI 키 없음, 조회 실패, 통신 끊김 | 캐시가 있으면 캐시, 없으면 내장 목록 |
| TTS 등록 실패 | 자막과 버튼으로 동작 |
| 저장된 상태를 읽지 못함 | 새로 시작 |
