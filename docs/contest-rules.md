## 제출

- 이메일 접수. 제목은 `[차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`.
- 접수양식(기획서)이 필수이고, 시연 영상과 GitHub 저장소는 선택이지만 가산점 대상입니다.
- 접수 메일에 저장소 주소와 최종 커밋 해시를 적습니다. 심사는 그 커밋을 기준으로 합니다.

## 저장소 요건

- 소스 코드와 release APK를 함께 올립니다. APK는 `apk/` 폴더에 `팀명_앱이름_release.apk` 이름으로 둡니다.
- 용량이 크면 GitHub Releases에 올리고 Release 주소를 제출합니다.
- README 필수 항목: 앱 이름과 한 줄 소개, 실행 방법, 테스트 환경 및 필요한 설정, 에뮬레이터 버전과 화면 규격, APK 위치 또는 Release 링크.
- API 키 같은 비밀값은 빼도 되고, 자체 서버 소스 제출은 필수가 아닙니다.
- 11/16까지 공개로 전환하지 않으면 개발 산출물 가산점이 반영되지 않습니다.

## 심사 항목 (배점 비공개)

1. 차량특화성: 모바일 대비 차량 환경만의 가치가 있는가, 주행과 정차 맥락 및 차량 기능과 결합됐는가
2. 창의성: 독창적인가, 운전자와 동승자의 불편과 해결 방식이 명확한가
3. 기술 활용성: Pleos Playground SDK와 API를 핵심 기능에 적절히 썼는가
4. 사업성: 타깃 고객, 예상 MAU, Retention, 확대 계획

2차 PT에서 시연한 결과물로 순위가 확정됩니다. PT 이후 추가 개발은 순위에 영향이 없습니다.

## 기술 범위 제한 (공지 "개발 범위 및 기술 문의 안내")

- 공개된 Pleos Playground 개발 문서의 SDK와 API 범위에서만 개발합니다.
- 쓸 수 있는 SDK: Vehicle, FusedLocation, NaviHelper, TextToSpeech, SpeechToText.
- Pleos LLM SDK는 제공되지 않습니다.
- **공모전 참가팀은 Gleo Interface(App Schema) 검토와 승인을 신청할 수 없습니다.**
- 차량 마이크 음성을 외부 음성 인식 서비스로 보내는 방식은 쓸 수 없습니다. 음성 인식은 SpeechToText SDK로 합니다.
- 개발 환경: Android API 28 이상, Gradle 8.0 이상, Java 또는 Kotlin.
- 운영사무국은 기능 구현과 API 동작 문의에 답하지 않습니다.
